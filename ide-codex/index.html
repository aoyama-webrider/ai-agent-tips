Codex VS Code 拡張機能 画像生成

VS CodeにCodexパネルを追加して、Claude Codeと並べて使う

想定環境: Windows / macOS / Linux ＋ VS Code 1.96.2以降 ＋ Codex拡張機能 ＋ ChatGPTのアカウント（Free / Go / Plus / Pro / Business / Edu / Enterprise。Windowsは推奨構成の初期設定に管理者権限が必要）

Claude CodeからCodexを呼ぶのとは別の話

Codexの使い方には2通りあります。
この記事は、VS CodeにCodexのパネルを追加する方式の話です。
先に違いを整理しておきます。

方式 どう動くか 向いている場面
Claude CodeからCodexを呼ぶ
（プラグイン）		 Claude Codeが指示役になり、Codexに下請けとして投げる Claude Codeでの作業の流れを止めずに、レビューや調査だけ任せたいとき
Codexパネルを開く
（この記事）		 Codex自体をエディタの相棒として直接動かす 自分でCodexと対話したいとき。画像生成のように、Claude Code経由ではできない作業

両方入れておくと、Claude Codeのパネルと並べてCodexのパネルを開ける状態になります。
作業内容に応じて、どちらに話しかけるかを選べるようになります。

並べて使う価値

  • その場で画像を生成できる。プラグイン経由では画像を生成できないので、パネルがあると資料用のカット画像を作る流れが切れない
  • 開いているファイルや選択したコードを、そのままCodexに渡せる。プロンプトを短く書ける
  • Claude Codeで書いたものを、隣のパネルにいる別のモデルにそのまま見せられる

セットアップ手順

所要時間は5分程度です。
Codex CLIを別途インストールする必要はありません（拡張機能が専用のCodex本体を同梱しています）。

1

拡張機能をインストールする

操作場所: VS Codeの拡張機能パネル

拡張機能パネル（Windowsは Ctrl + Shift + X）で「Codex」と検索します。
発行元がOpenAIのものを選んでインストールしてください。

項目 値
拡張機能名 Codex – OpenAI's coding agent
発行元 OpenAI
識別子 openai.chatgpt

検索結果に似た名前のものが並ぶことがあるので、識別子で見分けるのが確実です。
拡張機能の詳細画面を開くと、右側に識別子が表示されます。

2

ChatGPTアカウントでサインインする

操作場所: Codexパネル

インストールするとサイドバーにCodexのアイコンが増えます。
見つからない場合はコマンドパレット（Ctrl + Shift + P）で Open Codex Sidebar を実行してください。

パネル内のサインインボタンから、普段使っているChatGPTのアカウントでログインします。
すでにこのPCでCodexにログインしている場合は、その認証がそのまま使われます。

利用量はChatGPT側から引かれる

Codexを動かした分は、ChatGPT（Codex）側の利用上限を消費します。
Claudeのサブスクとは別枠なので、Claude Codeの残量には影響しません。

3

パネルの置き場所を決める

操作場所: VS Codeのサイドバー

Claude CodeとCodexのパネルを別々の場所に置くと、両方を同時に開いたまま作業できます。
サイドバーのアイコンはドラッグで移動できます。

拡張機能のREADMEでは、Codexのパネルを右側へ移す人が多いと紹介されています。
コードを左、AIとの対話を右にすると視線の移動が少なくなります。

使い方

画像を生成する

パネルに依頼文を書くだけで画像を生成できます。
ターミナルに切り替える必要がないので、資料を書きながら画像を差し込む流れが途切れません。

記事の見出し用に、ノートPCで作業する日本人男性の写真を生成して

保存先を指定しない場合、画像はCodexの作業フォルダ（~/.codex/generated_images/）に置かれ、そのパスが表示されます。
依頼文に「プロジェクトの public/images/ に保存して」のように書けば、Codexがそこへ移してくれます。

画像の指示は、用途と縦横比まで書くと精度が上がります。
「記事のアイキャッチ用に、横長（16:9）で」のように、置き場所を先に伝えるのがコツです。

画像生成はFreeプランでは使えない

Codex自体はFreeプランでも使えますが、画像生成はFreeプランの対象外です。
また画像生成を含むやり取りは、含まないものと比べて平均3〜5倍の速さで利用量を消費します。
APIキーで使っている場合は、画像生成にはAPI側の料金がかかります。

開いているファイルや選択範囲を渡す

コードや文章を選択した状態で右クリックすると、Codexのスレッドに追加するメニューが出ます。
プロンプトに貼り付けなくても、そのまま話題にできます。

コマンド 用途
Add to Codex Thread 選択した範囲を、いまの会話に追加する
Add File to Codex Thread ファイル全体を、いまの会話に追加する
New Codex Agent 別の作業用に、新しいスレッドを立てる
Open Codex Command Menu Codex関連の操作をまとめて呼び出す

いずれもコマンドパレット（Ctrl + Shift + P）から名前で実行できます。

TODOコメントから実装させる

コード内の TODO コメントの上に「Implement with Codex」というリンクが表示されます。
クリックすると、そのTODOの内容を実装する依頼がCodexに渡ります。
不要なら設定 chatgpt.commentCodeLensEnabled をオフにできます。

変えておくと快適な設定

設定画面（Ctrl + ,）で「chatgpt」と検索すると、この拡張機能の設定がまとめて出てきます。

設定 内容
chatgpt.openOnStartup VS Code起動時にCodexパネルを開く。既定はオフ
chatgpt.composerEnterBehavior Enterで送信するか、修飾キーとの組み合わせで送信するか。誤送信が多いなら変更する
chatgpt.followUpQueueMode 実行中に送った追加指示を、順番待ちにするか・軌道修正に使うか・中断するか
chatgpt.localeOverride CodexのUIの言語。空欄なら自動判定
chatgpt.commentCodeLensEnabled TODOコメント上の「Implement with Codex」を表示するか

触らないほうがよい設定

chatgpt.cliExecutable はCodex CLI本体を開発する人向けの項目です。
説明にも開発用途限定と書かれており、手で設定すると拡張機能が正しく動かなくなることがあります。
通常は空のままにしてください。

Windowsで使うときの注意

WindowsのCodexは、既定でWindows用のサンドボックス（実行を隔離する仕組み）を使います。
公式ドキュメントでも、WSLや仮想マシンを用意せずPowerShell上でそのまま動くと説明されています。
ファイルの編集まで任せる使い方も、この状態でできます。

WSLを使うかどうか

chatgpt.runCodexInWindowsSubsystemForLinux という設定があり、WSL（Windows上でLinuxを動かす仕組み）側でCodexを動かせます。
公式の案内では、既定はWindowsのサンドボックスのままでよく、WSLを選ぶのは次のような場合です。

  • Linux固有のツールが必要なとき
  • 作業環境がすでにWSL2の中にあるとき
  • Windowsのサンドボックスの2つのモードでは要件を満たせないとき

この設定を変更すると、VS Codeが再読み込みされます。

管理者権限を求められたとき

推奨されるWindowsサンドボックスは、管理者による初期設定が前提になっています。
初回はその設定のために権限を求められます。

会社の管理端末では先に確認する

この初期設定では、ローカルユーザーとグループの作成、ファイアウォールの設定、サンドボックス用ユーザーのログオン権限が必要です。
組織のポリシーでこれらが制限されていると失敗します。
管理端末で使う場合は、実行前にIT部門へ可否を確認してください。
公式の案内でも、失敗するときはIT部門に確認し、それまでは権限昇格が不要なモード（unelevated）を使うよう説明されています。
ただしこのモードは管理者権限を不要にするだけで、Codexを使ってよいかという組織の判断を代わりにするものではありません。
