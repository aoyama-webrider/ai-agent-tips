Claude Code Hook UserPromptSubmit IDE

IDE内のClaude Codeチャットに日時を表示する

想定環境: Windows ＋ Claude Code（IDE拡張のみ）＋ Claudeサブスク

なぜ日時表示が必要なのか

IDE内のClaude Codeチャットでは、各メッセージの送信時刻が画面に出ません。
少し前のやり取りを遡るときに、それがいつの会話だったのか分からず、作業の経過や時系列が把握しづらくなります。

Claude Code本体には showMessageTimestamps という設定がありますが、IDE拡張機能のチャットUIはこの設定を読みません（IDEがUIを独自に描画しているため）。
そのため、設定を true にしても効きません。

そこで「Claudeに毎回時刻を伝えて、返信の冒頭に文字として書いてもらう」運用にします。
UI実装に依存せず、チャット履歴に時刻が確実に残ります。

仕組み（2層構造）

[ユーザーがメッセージ送信] ↓ [Hook層] PowerShellでGet-Date実行 ↓ JSON形式でClaudeのコンテキストに注入 [Claude] 現在時刻を認識 ↓ グローバルCLAUDE.mdのルールに従う [返信冒頭に「YYYY-MM-DD HH:mm (曜日)」を出力] ↓ [チャット履歴に文字として日時が残る]

層1: フック（時刻を毎メッセージ注入）

Claude Codeの UserPromptSubmit フックを使い、ユーザーがメッセージを送信するたびに、現在のシステム時刻をPowerShellで取得してClaudeのコンテキストに渡します。

層2: ルール（返信冒頭に出力させる）

グローバル CLAUDE.md に「返信冒頭に日時を書く」というルールを記述し、Claudeに守らせます。
これにより、どのワークスペースで開いたセッションでも同じ挙動になります。

セットアップ手順

最短ルート: AIエージェントに任せる

手作業が不安なら、Claude CodeにこのページのURLを渡して、次のように頼むだけでOKです。
settings.json とグローバル CLAUDE.md の両方をAIが編集してくれます。

https://aoyama-webrider.github.io/ai-agent-tips/timestamp/
↑このページのとおり、私の環境に日時表示の設定を反映して。
・settings.json の hooks と、グローバルの CLAUDE.md の両方を設定して
・既存の設定は壊さず、マージして（上書きしない）
・終わったら、反映に再読み込み（/hooks を開き直す、または再起動）が必要か教えて

この前提なら、ほぼそのまま再現できます。
ただし最後の再読み込み（/hooks を開き直す、または再起動）だけは手動です。

反映する前に、追加される内容を見せてもらう

フックのコマンドは、あなたの権限でそのまま実行されます。
つまりWebページの内容をAIに読ませてフックに反映させる手順は、外部のページを設定の元ネタにする行為です。
ページが書き換えられていた場合、以降の全セッションで意図しないコマンドが動くことになります。
依頼するときは「反映する前に、追加する差分と実行されるコマンドを見せて」と付け加えてください。
内容を自分の目で確認してから許可するのが安全です。

仕組みを理解しながら自分で設定したい人向けに、手順も載せておきます。
所要時間は5〜10分程度です（Windows・PowerShell前提）。
Mac/Linuxの場合は Mac/Linuxで使うとき を参照してください。

1

settings.json にフックを追加

ファイル: C:\Users\<ユーザー名>\.claude\settings.json

hooks オブジェクトの中に、以下のブロックを追加します。
すでに hooks がある場合は中身を消さずにマージしてください（他のフックがあれば、それらを残したまま UserPromptSubmit を足す）。

{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "powershell.exe -NoProfile -Command \"[Console]::OutputEncoding = [System.Text.Encoding]::UTF8; @{hookSpecificOutput=@{hookEventName='UserPromptSubmit';additionalContext=('現在の日時: ' + (Get-Date -Format 'yyyy-MM-dd HH:mm:ss (dddd)'))}} | ConvertTo-Json -Compress\"",
            "timeout": 5
          }
        ]
      }
    ]
  }
}

Encoding注意

[Console]::OutputEncoding = [System.Text.Encoding]::UTF8; がないと日本語が文字化けします。
Windowsのコンソール出力はCP932（Shift-JIS系）が既定のため、ここでUTF-8に切り替えておく必要があります。

2

グローバルCLAUDE.mdにルールを追加

ファイル: C:\Users\<ユーザー名>\.claude\CLAUDE.md

このファイルは全プロジェクトで読み込まれるグローバルな指示書です。
以下のセクションを追加します。

## 返信フォーマット
- 各返信の冒頭に、現在の日時を `YYYY-MM-DD HH:mm (曜日略)` 形式で1行記載する（例: `2026-05-11 15:06 (月)`）
- 装飾記号や絵文字は付けず、テキストのみのシンプルな表記にする
- 日時は UserPromptSubmit フックで毎メッセージ注入される「現在の日時: ...」を参照する
- ツール呼び出しのみで終わるターン（テキスト出力がないターン）はスキップしてよい
- ユーザーから「時刻表示やめて」と言われたら停止する

グローバルCLAUDE.mdが効くわけ

プロジェクト別の CLAUDE.md に書くと、そのフォルダで開いたセッションでしか効きません。
複数フォルダで使いたい場合は、必ずグローバルCLAUDE.mdに書いてください。

3

設定を反映する

ここまでの2つを保存したら、以下のいずれかで読み込ませます。

  • Claude Codeを再起動する（確実）
  • チャット内で /hooks を一度開いて閉じる（フック設定だけが再読み込みされる）

CLAUDE.mdの編集はこの前に済ませる

グローバル CLAUDE.md はセッションの開始時に読み込まれます。
再起動したあとに編集しても、そのセッションには反映されません。
先にフックとCLAUDE.mdの両方を保存してから、この手順に進んでください。

4

動作確認

Claude Codeに何かメッセージを送ってみてください。
返信が次のように始まれば成功です。

2026-05-11 15:06 (月)

（ここから返信本文）

日時が出ない場合は次の項目をチェック。

  • settings.json のJSON構文が壊れていないか（カンマの抜けに注意）
  • フックがロードされているか（/hooks を開いて確認できる）
  • グローバルCLAUDE.md が正しい場所にあるか
  • セッションを再起動したか

よくある疑問・注意点

Mac/Linuxで使うとき

PowerShellの代わりにシェルコマンドでフックを書きます。
command の中身をたとえば以下のように差し替えてください。

"command": "echo \"{\\\"hookSpecificOutput\\\":{\\\"hookEventName\\\":\\\"UserPromptSubmit\\\",\\\"additionalContext\\\":\\\"現在の日時: $(date '+%Y-%m-%d %H:%M:%S (%a)')\\\"}}\""

表示をやめたいとき

  • 一時的にやめるだけなら、Claudeに「時刻表示やめて」と伝える
  • 完全にオフにするには settings.json の UserPromptSubmit フックを削除＋グローバル CLAUDE.md の該当セクションを削除

秒単位まで表示したい場合

CLAUDE.md のフォーマット指定を YYYY-MM-DD HH:mm:ss (曜日) に変えるだけです。
フック側は元から秒まで取得しています。

タイムゾーンはどう扱われるか

Get-Date はPCのローカル時刻を返します。
海外出張などでJSTを明示したい場合は、フォーマットに K（タイムゾーンオフセット）を追加します。

IDE内蔵のAI機能には効かない

このフックはClaude Codeプラグイン専用です。
IDE内蔵のAI機能（インラインチャットなど）はAnthropicとは別のAPI経路で動いているため、この設定の影響を受けません。

ワークスペース別の記憶（メモリ）と併用するとき

記憶ファイル（~/.claude/projects/<sanitized-cwd>/memory/）に同じルールを書いても効きますが、ワークスペース単位の効力範囲なので注意が必要です。
全セッション共通にしたいルールは、グローバルCLAUDE.mdに書くのが原則です。

UserPromptSubmitフックの活用例

このフックは「ユーザーがメッセージを送るたびに、Claudeに渡すコンテキストを動的に追加できる窓口」として汎用的に使えます。
日時表示はその一例にすぎません。

応用アイデア

注入する情報 使いどころ
現在のGitブランチ名 「いまどのブランチで作業しているか」をClaudeが自動把握。ブランチ切り替え時の混乱を防げる
カレンダーの次の予定までの時間 「あと20分でMTGなので、簡潔に」とClaude側が配慮できる
バッテリー残量 ノートPCの外出作業時。残量が少ないと手短にまとめてくれる
未読Slack件数 割り込み状況の把握。集中作業中なら通知をミュート、など
天気・気温 外出予定の判断、雑談の話題
直近の作業ログ要約 長時間セッションで「さっきまで何やってたっけ」を防ぐ

実装パターン

この記事の日時のフックには変数（$）が出てきません。
いっぽう、Gitブランチのように途中の値を変数に入れる処理では、1行で書くと壊れます。
理由は次の注意にまとめました。

フックのコマンドに $ を直接書かない

フックのコマンドは、既定でbashに渡されます（Windowsでも、Git Bashが入っていればbash経由になります）。
そのため $branch のような変数をそのまま書くと、bashが先に展開して空になり、PowerShellには届きません。
2>$null も 2> だけになり、構文エラーになります。
回避策は2つあります。
1つは、JSON内で \\$branch と書いて、PowerShellに $ を渡す方法です。
もう1つは、処理を .ps1 ファイルに出して、フックからはそれを呼ぶ方法です。
行数が増えるものは後者が確実です。

1行で書く場合は、$ を \\$ にします。

"command": "powershell.exe -NoProfile -Command \"[Console]::OutputEncoding = [System.Text.Encoding]::UTF8; \\$branch = (git branch --show-current 2>\\$null); if (-not \\$branch) { \\$branch = 'no-git' }; @{hookSpecificOutput=@{hookEventName='UserPromptSubmit';additionalContext=('現在のブランチ: ' + \\$branch)}} | ConvertTo-Json -Compress\""

複数の情報を1つのフックでまとめて渡す

フックを複数登録する代わりに、1つのフック内で複数の情報をまとめて additionalContext に入れる書き方が推奨です。
フックが多いと、セッション開始時や各メッセージごとに余分なプロセスが立ち上がるためです。

ここまで長くなると1行では書きにくいので、.ps1 ファイルにします。

ファイル: C:\Users\<ユーザー名>\.claude\context.ps1

$dt = Get-Date -Format 'yyyy-MM-dd HH:mm (dddd)'
$branch = (git branch --show-current 2>$null)
$ctx = "現在の日時: $dt`n現在のブランチ: $branch"
@{hookSpecificOutput=@{hookEventName='UserPromptSubmit';additionalContext=$ctx}} | ConvertTo-Json -Compress

フック側は、このファイルを呼ぶだけにします。

"command": "powershell.exe -NoProfile -File \"C:\\Users\\<ユーザー名>\\.claude\\context.ps1\""

日本語を含む .ps1 はUTF-8 BOM付きで保存する

上の .ps1 には日本語が入っています。
BOMなしのUTF-8で保存すると、Windows PowerShellが別の文字コードとして読み、文字化けや構文エラーになります。
エディタの保存形式を「UTF-8 with BOM」にしてください。

他のフックイベント

UserPromptSubmit 以外にも、Claude Codeにはさまざまなフックイベントがあります。

イベント 発火タイミング 用途例
PreToolUse ツール実行前 危険コマンドをブロック、ログ記録
PostToolUse ツール実行後 編集後にフォーマッターを自動実行、テストを走らせる
Stop Claudeが返答を完了したとき 音を鳴らす、Slackに通知
SessionStart セッション開始時 初期コンテキスト注入、環境チェック
PermissionRequest 権限要求時 音を鳴らして気づかせる

運用上の注意

フックは毎メッセージ、毎ツール実行ごとに走るので、重い処理を書くと体感速度が落ちます。
timeout を短め（5〜10秒）に設定し、ネットワーク呼び出しなどブロッキングする処理は避けましょう。
