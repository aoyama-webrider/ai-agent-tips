Claude Code Codex プラグイン 画像生成

Claude CodeからCodexを呼び出して、レビューと画像生成に使う

想定環境: Windows ＋ Claude Code（CLI）＋ Node.js 18.18以上 ＋ Claudeサブスク ＋ ChatGPTのアカウント（初回のみ管理者権限が必要）

Codexを併用する価値

Claude CodeとCodexは、どちらもターミナルで動くコーディングエージェントです。
片方だけでも仕事は進みますが、行き来できるようにしておくと次の2点で効きます。

1. 別の視点でレビューできる

同じAIに「これでいい？」と聞くと、自分が書いたものを自分で採点する形になりがちです。
Claude Codeで書いた文章やコードをCodexに渡すと、書いた経緯を知らない相手からの指摘が返ってきます。
論理の飛躍や説明不足のように、書いた側では気づきにくい箇所が出てきます。

2. 画像を生成できる

Codexには画像生成の機能があり、資料や記事に使うカット画像をその場で用意できます。
ただしプラグインには画像生成用のコマンドがないため、実際に作るときはターミナルのCodexを使います。
手順は後半の 活用2 にまとめました。

利用量はChatGPT側から引かれる

このプラグインは、PCに入っているCodex CLIを呼び出しているだけの仕組みです。
そのため使った分はChatGPT（Codex）側の利用上限を消費し、Claudeのサブスクとは別枠になります。
Codex自体はFreeプランを含むどのプランでも使えます（OpenAIのAPIキーでも可）。
ただし画像生成はFreeプランの対象外です。

セットアップ手順

所要時間は15分程度です。
プラグインの導入は、IDEのチャット画面からもできますが、この記事ではターミナルで claude を起動したCLI版で進めます。
認証やサンドボックスの初期設定でターミナルの操作が入るため、そのほうが手順どおりに進めやすいからです。

この手順は自分で進めるのが確実

ブラウザでのログイン認証や、Windowsの管理者権限のダイアログなど、人が操作する場面が含まれます。
AIエージェントに丸ごと任せると途中で止まるので、以下を順に進めてください。

1

Claude Code CLI があるか確認する

実行場所: IDEのターミナル

Codexプラグインを入れるには、CLI版のClaude Codeが必要です。
まずバージョンを確認します。

claude --version

バージョン番号（例: 2.1.91）が表示されればOKです。
「コマンドが見つかりません」と出た場合は、次のコマンドでインストールしてください。

irm https://claude.ai/install.ps1 | iex

これはWindows（PowerShell）用のインストールコマンドです。
Mac/Linuxの場合はインストール方法が異なるので、公式の手順を確認してください。

2

Claude Code をCLIで起動する

実行場所: IDEのターミナル

claude

以降のスラッシュコマンドは、この画面に入力します。

3

Codexプラグインを入れる

実行場所: Claude Code CLI

OpenAIが公式に配布している codex-plugin-cc を使います。
次の3つを1行ずつ実行します。

まずマーケットプレイス（プラグインの配布元）を追加します。

/plugin marketplace add openai/codex-plugin-cc

次にプラグインをインストールします。

/plugin install codex@openai-codex

最後に再読み込みして反映させます。

/reload-plugins

正常に進むと、読み込んだプラグイン・スキル・エージェント・フックの数が表示されます。
数はプラグインの更新で変わるので、エラーが出ていなければ問題ありません。

4

Codex CLI をセットアップする

実行場所: Claude Code CLI

/codex:setup

このコマンドで次のことが行われます。

  • Codex CLIがPCに入っているかの確認
  • 入っていない場合は「インストールしますか？」と聞かれる（「はい」を選ぶ）
  • ChatGPTアカウントでのログイン状態の確認

インストール時には、内部で npm install -g @openai/codex が実行されます。
そのためNode.jsとnpmが必要です。
プラグイン側の要件はNode.js 18.18以上なので、先に node --version で確認しておくと途中で止まりません。

5

ChatGPTアカウントで認証する

実行場所: Claude Code CLI

ログインが済んでいない場合は、次を実行します。

!codex login

先頭の ! は、Claude Codeのチャット欄からターミナルのコマンドを直接実行するための記号です。
ブラウザが自動で開くので、普段使っているChatGPTのアカウントでログインしてください。
すでにこのPCでCodexにログインしている場合は、その認証がそのまま使われるのでこの手順は不要です。

6

サンドボックスの初期設定（Windowsのみ・初回だけ）

実行場所: IDEのターミナル

codex

初回起動時は、サンドボックス（Codexの実行を隔離する仕組み）の選択画面が出ます。

1. Set up default sandbox (requires Administrator permissions) ← 推奨 2. Use non-admin sandbox (higher risk if prompt injected) 3. Quit
  1. 「1. Set up default sandbox」を選んでEnterを押す
  2. Windowsの管理者権限の確認ダイアログ（UAC）が出るので、プログラム名と発行元を確認する
  3. 「はい」をクリックする

選択肢1を選ぶと、Codexが実行するコマンドをOSの機能で隔離した状態で動かせます。
選択肢2はその隔離が弱く、外部から不正な指示を読み込んだ場合の影響が大きくなります。
管理者権限を求められるのは最初の設定時だけなので、通常は選択肢1を選んでください。

会社の管理端末では先に確認する

この初期設定では、ローカルユーザーとグループの作成、ファイアウォールの設定などが行われます。
組織のポリシーで制限されていると失敗します。
管理端末で使う場合は、実行前にIT部門へ可否を確認してください。
確認が取れるまでは、権限昇格が不要な選択肢2で試すこともできます。

活用1: 別の視点でレビューさせる

Claude Codeで書いたものを、そのままCodexに渡してレビューさせます。
対象が文章かコードかで、使い方が変わります。

文章・資料をレビューさせる

文章のレビューは専用コマンドではなく、普通の依頼文で頼みます。
Claude Codeがプラグイン経由でCodexに投げてくれます。

以下の観点でCodexにレビューしてもらって
1. 論理の飛躍・根拠不足
2. 想定読者にとってわかりにくい箇所
3. 構成の改善余地（見出し・順序）
4. 表記揺れ・用語の不統一
5. 総合評価と、優先度をつけた改善案

観点を並べて渡すのがコツです。
「レビューして」だけだと感想に近い返答になりやすく、直すべき箇所が絞れません。

コードをレビューさせる

コードにはGitの差分を見る専用コマンドがあります。

コマンド 何をするか
/codex:review いまの変更（未コミットの差分）を通常の観点でレビュー
/codex:review --base main mainとの差分＝ブランチ全体をレビュー
/codex:adversarial-review 設計や方針そのものを疑う、厳しめのレビュー。観点を書き添えられる

いずれも読み取り専用で、コードは書き換えません。
ファイル数が多いと時間がかかるので、--background を付けて裏で走らせるのが現実的です。

/codex:review --background
/codex:status
/codex:result

/codex:status で進行状況を確認し、終わったら /codex:result で結果を受け取ります。

修正まで任せたいときは /codex:rescue

指摘をもらうだけでなく、調査や修正まで任せたいときは /codex:rescue を使います。
「なぜテストが落ちるのか調べて」のように、依頼内容を続けて書きます。
時間がかかることが多いので、こちらも --background と併用するのがおすすめです。

活用2: 画像を生成する

プラグインには画像生成用のコマンドがありません。
そのため確実に呼び出したいときは、ターミナルで codex を直接起動します。
VS Codeを使っているなら、Codexのパネルを追加するほうがターミナルへの切り替えも不要になります。

1

対話モードを起動する

実行場所: IDEのターミナル

codex

OpenAI公式のCodex CLIが起動し、TUI（文字ベースの操作画面）が開きます。

2

画像をリクエストする

実行場所: Codex TUI

日本人の男性会社員の写真を生成

画像生成の機能を明示的に呼び出したい場合は、依頼文に $imagegen を含めます。
位置は先頭でも末尾でもかまいません。

3

生成された画像を受け取る

完了するとCodexがファイルパスを表示します。

file:///C:/Users/<ユーザー名>/.codex/generated_images/019dffc6-.../ig_xxxxx.png

保存先を指定しなければ、Codexの作業フォルダに置かれたままになります。
依頼文に「プロジェクトの public/images/ に保存して」のように書けば、Codexがそこへ移してくれます。
プロジェクトから参照する画像は、作業フォルダに置いたままにしないでください。

プロンプトが貼り付けられないとき

Codex TUIは Ctrl + V を画像の貼り付けに割り当てています。
そのため文字を貼り付けたいときは効かないことがあります。
その場合は右クリック、またはターミナル側の貼り付け操作（Windows Terminalなら Ctrl + Shift + V）を使ってください。

コマンド早見表

Claude Code CLIで使う（プラグイン）

コマンド 用途
/codex:setup 初期設定と状態確認
/codex:review Git差分のコードレビュー（読み取り専用）
/codex:adversarial-review 設計・方針を疑う厳しめのレビュー
/codex:rescue 調査や修正をCodexに任せる
/codex:status バックグラウンドジョブの状態確認
/codex:result 終わったジョブの結果を表示
/codex:cancel 実行中のジョブを中止

ターミナルで直接使う（Codex CLI）

コマンド 用途
codex 対話モード（TUI）を起動
codex exec "..." 対話せずワンショットで実行
codex login / codex logout 認証と解除
codex resume 前回のセッションを開いて続きから作業
npm i -g @openai/codex@latest 最新版へ更新
/status TUI内で利用量・状態を確認

よくある疑問・注意点

レビューを自動化する「レビューゲート」は要注意

/codex:setup --enable-review-gate を実行すると、Claudeが応答を終えるたびにCodexのレビューが走るようになります。
指摘が出た場合は応答の終了がブロックされ、Claudeが直してから終わる流れになります。
便利ですが、ClaudeとCodexが延々と往復して利用量を大きく消費することがあります。
常時オンにはせず、様子を見ていられるときだけ有効にしてください。
戻すときは /codex:setup --disable-review-gate です。

使うモデルや推論の強さを変えたい

Codex側の設定ファイルで指定します。
全体に効かせるなら ~/.codex/config.toml、プロジェクト単位なら .codex/config.toml です。

model = "gpt-5.4-mini"
model_reasoning_effort = "high"

プラグインはこの設定をそのまま読みます。
ただしプロジェクト単位の設定は、そのプロジェクトを信頼済み（Codexがそのフォルダを安全と認識している状態）にしていないと読み込まれません。

Codexの続きをCodex側で作業したい

/codex:result や /codex:status にはセッションIDが表示されます。
そのIDを codex resume <セッションID> に渡すと、同じ作業をCodex側で開き直して続けられます。

Codex用に別アカウントを用意する必要はあるか

不要です。
このプラグインはPCに入っているCodex CLIの認証をそのまま使うため、すでにCodexにログインしていればそのアカウントで動きます。
